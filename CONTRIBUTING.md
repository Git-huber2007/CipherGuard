# Contributing

## Setup

You need Python 3.10 or later.

```bash
git clone https://github.com/Git-huber2007/CipherGuard.git
cd CipherGuard
pip install -r requirements.txt
pip install -e ".[dev]"
pre-commit install          # optional: lint on every commit
```

Generate the sample captures and train the model once. The dashboard and
`analyze` need both.

```bash
cipherguard lab
cipherguard train
```

## Checks

Run these before opening a pull request. CI runs the same two.

```bash
ruff check .
python -m pytest tests/
```

The full suite takes about three minutes. `-m "not soak"` skips the two
long-running resource tests. `make test` and `make lint` do the same thing if
you have `make`.

## Rules for changes

- Read the "Design rules" section of `ARCHITECTURE.md` first. A change that
  decrypts traffic, keeps payload bytes or makes an outbound call will not be
  merged.
- New behaviour needs a test. A bug fix needs a test that fails without it.
- Edit the dashboard in `cipherguard/api/static/`. `docs/` is generated by
  `cipherguard export-demo`, and the Pages workflow rebuilds it.
- A new audit rule needs an ID, a reference to the standard it comes from and
  a plain-language sentence in `cipherguard/audit/plain.py`.
- Keep observed values and inferred values separate in any new output.

## Pull requests

- Work on a branch and open a pull request against `main`.
- Keep one change per pull request.
- Write commit messages that say what changed and why.
- Add a line to `CHANGELOG.md` under "Unreleased" for anything a user would
  notice.

## Reporting bugs and vulnerabilities

Use the issue templates for bugs and feature requests. Report vulnerabilities
privately as described in `SECURITY.md`.
